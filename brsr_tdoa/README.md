# BRSR-TDOA

本目录实现“有限比特贝叶斯风险驱动的 TDOA 逐层频谱采集与精化”
（BRSR-TDOA）的阶段 A 最小可证伪实验。它不导入或修改 `main.py`、
DAE、V5、urban8、PASR 和 PFRS。

当前目录同时包含阶段 B 的独立开发门禁。阶段 A 已冻结；阶段 B 不改写
阶段 A 的核心文件或结果。

## 阶段 A 回答的问题

1. 在随机公共频谱、未知复增益和有限 TDOA 先验下，能否构造严格归一化的
   联合后验？
2. 固定公共范围的嵌套 I/Q 量化能否支持粗码和追加 bit 的精确区间似然？
3. “新增信息后的期望后验风险不增加”是否由数值实验验证？
4. 一步前瞻动作与同决策深度的精确贝尔曼动态规划基准之间有多大差距？
5. 计入载荷、动作索引和停止信令后，动态策略是否仍有风险—bit 潜力？

阶段 A 不验证 CR16、urban8 或最终定位性能，也不允许据此声称超过现有
DAE 或强压缩基线。

## 严格概率模型

- DFT 长度为 `N=1024`，显著大于有限 TDOA 假设数。
- 公共频谱逐频点服从圆对称复高斯先验。
- TDOA 和复增益均使用显式有限先验，复增益相位网格均匀覆盖完整相位圆，
  估计器不知道真实状态。
- A 端观测后，公共频谱被解析边缘化，得到 B 端逐频点条件复高斯分布。
- B 端先除以由公开 SNR 条件和先验二阶矩唯一确定的预测均方根尺度，再使用
  固定归一化量化范围。该尺度不依赖任何样本观测或真值，因此不产生隐藏
  scale bit；B 端条件均值和方差同步缩放。
- B 端量化码的似然使用高斯分布在量化区间上的精确积分，并在对数域完成
  贝叶斯更新，避免高信噪比错误假设被人为概率地板污染。

## 通信协议

- 基础频点按预共享调度发送，不收动作索引。
- 每个后续 `acquire/refine` 动作均收固定长度动作码和真实新增 I/Q bit。
- 终止会发送 stop 动作码。
- 归一化量化范围和动作码本公开固定；逐 SNR 标准化尺度由公开协议参数
  确定，因此阶段 A 没有隐藏的逐样本尺度或频点索引。
- A 端完整局部观测在阶段 A 暂不计通信量；该假设会写入 manifest，后续
  多 UAV 阶段必须把参考端预算纳入总账本。

## 运行

在 PyCharm 中直接运行 `run_stage_a.py`。文件顶部
`PYCHARM_RUN_MODE="research"`，默认执行阶段 A 正式机制验证。完整运行由
用户执行。

Codex 轻量检查使用：

```powershell
D:\Software\anaconda3\envs\PyTorch\python.exe brsr_tdoa\run_stage_a.py --mode smoke
```

结果写入 `运行结果/BRSR_STAGE_A_<时间戳>_<模式>/`，包括逐样本 CSV、动作
诊断、动态规划诊断、SNR/总体汇总、三张 SVG、`validation.json`、
`go_no_go.json`、`manifest.json` 和 `run.log`。

动态规划方法名含 `DiagnosticSubset`，只在每个 seed/SNR 的预注册小样本上
运行，用于检查一步前瞻与同决策深度精确贝尔曼基准的差距；它不是无限时域
全局上界，也不得把其 RMSE 与全样本方法直接排名。

## 结果边界

`SMOKE_ONLY` 只验证代码和协议。`STAGE_A_MECHANISM_PASS` 也只表示后验校准、
风险单调性、动作校准和动态规划值关系达到预注册门槛，不能直接进入论文
性能结论；后续仍须经过 CR16 等比特开发门禁和全新 locked 场景。

正式门禁不会在 locked 集合上选择通信代价。所有预注册贪心策略都必须满足
覆盖率要求；动作机制使用按独立 `(seed, trial)` 轨迹聚类的“实际后验风险
减去期望后验风险”均值检验。Spearman 相关和事后最优动作一致率仅作描述，
不作为通过条件。

## 阶段 B：结构化 BPSK-RRC 开发门禁

阶段 B 的入口为 `run_stage_b.py`。它直接使用更接近通信信号的完整
`1024` 点 BPSK-RRC 波形，不单独运行完整模型匹配轨道；必要的 FFT、
时延符号、线性分数时延和嵌套量化检查嵌入脚本，并另由
`test_brsr_core.py` 与 `test_brsr_stage_b.py` 验证。

### 正式场景

- 采样率 `40 MHz`，每符号 `2` 点，RRC 滚降系数 `0.2`、跨度
  `8 symbols`。
- TDOA 在 `[-8,8] samples` 连续生成，使用带保护区的线性分数时延，
  不使用循环移位。
- 未知复增益的幅度连续分布于 `[0.7,0.9]`，相位连续覆盖完整相位圆。
- 两站使用独立复高斯白噪声；SNR 是增益前的名义源信号 SNR。第一轮不含
  多径、NLOS 和路径损耗，避免把波形模型、逐层策略与信道失配混在一起。
- A 站位于融合端，其本地观测不计通信量；B 站可缓存预共享候选池的
  全精度 FFT，并根据反馈发送追加 bit。该非对称部署假设会写入
  `manifest.json`。

### 候选频点与工作后验

- 候选池只包含 RRC 理论有效带内的正频率。基础两频点满足无歧义周期大于
  整个 TDOA 支持；其余频点按理论 `RRC功率 × 角频率平方` 的累计分位点
  覆盖中高频。
- 候选设计不读取性能标签或未来 locked 数据。development clean A
  波形只用于冻结候选频点功率和检查最低功率门槛。
- 脚本额外保存候选频点的完整复协方差，用于量化频点相关性。主后验仍使用
  逐频点复高斯工作模型，因为相关复高斯变量经过逐分量有限 bit 量化后，
  精确序贯似然需要高维截断复高斯矩形概率；当前代码不以未经验证的独立性
  近似冒充“完整协方差精确后验”。
- 因此，后验风险、可信区间覆盖率和经验均方误差之比都是正式门禁，而不是
  仅作装饰的诊断。

### 量化与通信账本

- 每个实部和虚部先发送 `4 bit` 粗码，再追加到 `8 bit`；8 bit 是一个
  实数的最终量化精度。
- 基础层固定发送两个频点，共 `16 bit`。12 个候选频点下，动作码本含
  stop、acquire 和 refine，共需 `5 bit` 反馈。
- 提前停止需要发送 stop 码；达到两次决策硬上限后自动终止，不再收费。
  因而自适应协议的总通信量只能取约 `21--42 bit`，目标平均预算为
  `24/32/40 bit`。
- 静态与 SNR-only 调度预共享，不收逐样本动作码；这是它们不自适应所对应
  的真实通信优势。所有方法比较总 bit，不把 payload 和反馈混为一谈。
- 本阶段的 `24/32/40 bit` 是 B 站逐观测预算，不等同于主项目的 CR16。

### 公平对比

- `Best-Static`：在独立 calibration 种子池中穷举预算内全部可辨识
  `0/4/8 bit` 固定配置，冻结后在 evaluation 种子池评估。
- `SNR-only`：同样只在 calibration 池中按每个 SNR 选择固定配置；它知道
  公开 SNR，但不看逐样本后验。
- `BRSR-Greedy`：精确枚举下一动作的量化结果，最小化一步后验风险与新增
  bit 代价。
- `BRSR-Rollout`：使用后验预测采样近似两步贝尔曼前瞻；正式配置使用
  `Q=16`，并在每个 SNR 的预注册单样本上报告 `Q=16/32/64/128` 收敛。
- `Base-4bit/Base-8bit/All-4bit/All-8bit`：用于解释基础层和量化上限，
  不作为同预算强基线。

完整 `4->8 bit` 两步精确动态规划需要对每个动作展开最多 256 个复量化
结果，再递归展开第二层，在正式假设网格上计算量不合理。阶段 B 不把剪枝
近似标成 Exact-DP；精确贝尔曼递归只在模型匹配的小状态 Track M 单元测试
中验证，正式 Track S 使用明确标注的 Monte Carlo Rollout。

### 数据隔离与运行

阶段 B 的 development 内部再划分三个互斥种子池：

1. `prior_seeds`：估计候选频点功率和协方差诊断；
2. `calibration_seeds`：选择拉格朗日乘子、Best-Static 和 SNR-only；
3. `evaluation_seeds`：只报告开发性能和门禁，不参与上述选择。

在 PyCharm 中直接运行 `run_stage_b.py`，文件顶部默认为：

```python
PYCHARM_RUN_MODE = "development"
```

Codex 轻量检查使用：

```powershell
D:\Software\anaconda3\envs\PyTorch\python.exe brsr_tdoa\run_stage_b.py --mode smoke
```

结果写入 `运行结果/BRSR_STAGE_B_<时间戳>_<模式>/`。主要输出包括逐样本
CSV、SNR/总体汇总、拉格朗日校准表、静态计划、候选频点与协方差诊断、
Rollout 样本数收敛表、链路自检、3 张 SVG、开发门禁和 manifest。
长运行期间会覆盖保存 `.partial.csv`；完整成功后自动删除，不改变最终目录
文件结构，中途异常时可保留已完成方法的证据。

`SMOKE_ONLY` 只说明代码链和协议可运行。只有 development 同时满足同平均
bit 的精度增益或同精度 bit 节省、逐 SNR 不严重退化、轨迹聚类置信区间、
后验校准和低截幅门槛，才输出 `READY_FOR_NEW_LOCKED_DESIGN`；脚本本身
不会创建 locked 结果。

### 阶段 B 第一阶段失败机理诊断

`diagnose_stage_b_failures.py` 只读取冻结的 Stage B development 结果，并
按原 manifest、候选频点、功率、量化器、种子和工作后验重建诊断样本。
它不会修改 `run_stage_b.py`、正式策略或原结果目录。

诊断分别输出：

- 线性分数时延与有限窗截取相对理想逐频点相移模型的无噪声残差；
- 固定已传输码下的正式粗复增益网格、细网格和真值增益上界；
- 同一两动作空间内的事后停止/动作上界；
- 预注册少量样本上的 Rollout 样本数稳定性；
- 当前候选池的未知增益投影局部信息代理和多尺度模糊函数审计。

真值复增益和真值 TDOA 只用于上界诊断，不是可部署方法。候选池审计也是
未量化的离线代理，不会在本轮重新选频。PyCharm 默认模式为
`PYCHARM_RUN_MODE="diagnostic"`；Codex 冒烟使用：

```powershell
D:\Software\anaconda3\envs\PyTorch\python.exe `
  brsr_tdoa\diagnose_stage_b_failures.py --mode smoke
```
